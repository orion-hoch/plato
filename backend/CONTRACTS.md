Whole files that went are in `archive/v10-removed/`. **v11, no schedule:** the study plan (days, minutes a day, minutes per goal, urgency) is gone; a session's goal is a topic plus an understanding target, chosen by need (Session › Agenda). Its files are in `archive/v11-removed/`.

## Conventions

- Node 24 ESM, no new npm dependencies. Record shapes are the spec's, plus `scope` on every stored record.
- Storage: `app.db` (`backend/core/db.mjs`); tables in `backend/db/migrations/*.sql`, a new migration per change, numbered after the last (001 core, 010 knowledge, 020–021 learner, 030–031 questions, 040–049 session and director, 080 modules, 082 studies; 045/046/070 were dropped by 048/049/081). `teaching_plans` and `context_packets` (040) are v10 leftovers that nothing reads or writes. `insert / update (CAS on rowVersion) / get / find / tx`; append-only tables are never updated.
- Cross-module reads go through `app.services.<module>` (one exception: the learner reads the `topic_migrations` rows a `knowledge.published` names).
- Events: `app.events.emit(...)` inside the state-changing transaction; consumers via `app.events.subscribe(name, types, handler)`, synchronous, usually enqueueing jobs.
- Jobs: `app.jobs.register(type, async (payload, ctx) => …)`; results commit with `ctx.commit(() => …)`. Throw `AppError` with a spec code; retryable codes back off.
- Providers take `work: WorkIdentity` and return `CallResult<T>`, called through `call(adapterFn, input, { valueSchema })` (`backend/providers/contracts.mjs`); a failed or malformed result is never a success. Mocks: `backend/providers/mock/<module>.mjs`, `create<Module>Mocks({ clock, controls })`. Live: `backend/providers/codex/<module>.mjs` over the model gateway; `role` names a lane in `server/runtime.mjs` (`astra` and `plato` are `heavy` and `light`). Prompts: `backend/providers/prompts/<module>.mjs`, a version per template.
- Shared helpers (v10, audit §4): `safe(fn, fallback)` in `core/util.mjs` (best-effort edges only; `BACKEND_DEBUG` logs what it swallowed); `core/match.mjs` (below); `core/fanout.mjs` (below); `shared/boards.mjs` (below).
- Tests: `backend/test/acceptance/AXX-*.test.mjs` on `createTestBackend()` (real database, jobs, outbox and blobs; mock providers); `app.drain()` runs background work, `app.clock.advance(ms)` moves time.
- Never return or log secrets; never put expected answers, rubrics, diagnoses, source excerpts or confidence into student-facing results.

### Words and topics (`core/match.mjs`)

One tokenizer for every "which of these does the text mean": retrieval hits, the teaching engine, change_topic, examUnit, ingest, elements.
- `words(text)` → the content words: lowercase letters and digits, three or more, a plural's s cut, never a `STOP` word (function words, request filler such as "exam problem", "practice", "work through", and the course's structural words "module", "topic", "unit", "lecture"). `overlap(a, b)` counts `a`'s words in `b` (texts or word sets).
- `looksLikeExam(name)`: a word starting prelim, midterm, practice, final, quiz or exam (never "example").
- Topic views: `expandTopics(view, ids)` (a unit includes its descendants), `unitOf(view, topicId)`, `unitRoots(view)`, `matchTopic(view, about)` (title words count double, then description and objectives; at least 2; the narrower topic wins a tie), `matchGoal(view, goals, about, { topics })` (at least half the asked words in its title and topics' titles).

### Streaming and deadlines (`core/fanout.mjs`)

- `partialJson(text)`: the fields a streaming JSON text has completed (a field appears only when complete), else null.
- `onFields(steps)` → an `onText` for a streamed call: each `{ when(partial), run(partial) }` runs once, the first time `when` holds; parsing stops when all have run.
- `within(promise, ms, fallback = null)`: the promise, or `fallback` once `ms` pass (slow work gives way, it is not stopped).

### Boards (`shared/boards.mjs`, backend and page)

- `BOARD_KINDS` (`markdown diagram element zone question check notes`), `ELEMENT_KINDS`, `CHECK_KINDS`, `MAX_MARKDOWN` (1,400).
- `checkBoard(board, { questions }?)` → `{ board, problem }`: the board ready for the page, or null, and what is wrong. Shapes: `markdown { title, content }` (over 1,400 chars is a problem and is cut); `diagram { title, diagram: { type, data } }` (it must draw: `checkDiagram`, src/visuals/diagram.mjs; data may be JSON text; a formula comes back normalized); `zone { zone: { kind: 'code' + language 'c'|'riscv', or 'latex' + lines; starter?, lines?, task? } }`; `check { check: { kind, prompt, options (choice, multi_select: 2+), items (order: 2+), left and right (match: 2+, paired) } }`; `question { questionId, question? }` (only an id in `questions`, when given); `notes { ref?, query?, quote?, lecture? }`; `element { element: { kind, spec, title?, summary? } }`.
- `fromDraft(draft)`: a model's flat board (`diagramType`, `diagramData` as JSON text, …) in the page's shape. `standIn(board)`: its markdown, else its diagram, else null.
- The course model reports a board's problem for its repair; the engine falls back to the stand-in; the page draws only a checked board.

## Learner (`backend/learner`, `app.services.learner`)

- Hook `app.hooks.examCreated` bootstraps the profile (§2.3). `profile`, `contextRef`, `selectedFacts`, `topicStates`, `recordFeedback(scope, { …, type: 'preference'|'goal'|…, key? })` → `{ feedbackId, learnerChangeId|null, exclusionReason|null }`, `commitInteraction(scope, fields)` (enqueues `assess_answer` only for an eligible reply to a posed graded question), `supersedeInteraction`, `projection`, `projections` (unknown: `status:'unknown', displayIndex:null`), `observe`, `estimates` → `{ topics, concepts }`, `conceptStates`, `history`, `personalView(scope, km)`, `latestPersonalManifestId`, `setFocus`; admin `decisions`, `changes`, `assessments`.
- Consumes `knowledge.published`, `learner.changed`, `profile.changed`, `exam.deleted`; emits `learner.changed`, `personal.decided`, `personal.published`, `profile.changed`. Jobs: `assess_answer`, `assess_response` (only a graded reply with no findings), `update_learner`, `refresh_exam_profile`, `reconsider_personal`, `publish_personal`.
- **Preferences:** a preference's key is `key || preferenceKey(text)` (remember_preference's `about`: help_wanted, explanation_order, pace, detail, practice_style, visuals, goal, study_time, teaching_balance, background, exam_date, exam_scope, other); "other" and "goal" keep the text key. Goals, help_wanted and exam_scope are exam-level. A keyed statement is never dropped as an acknowledgment, and the key is part of the feedback's identity.
- **The learner model** (`learner/model.mjs`, table `learner_observations`, migration 021): ability θ with uncertainty σ per concept and per topic on the logit scale, level difficulty recall −1, explain −0.4, apply 0.3, transfer 1, exam 1.6, `P = 1 / (1 + e^−(θ − d))`.
  - Update per observation (outcome o 0–1, assistance a 0–1): `I = P(1 − P)`, `w = 1 − a` for a success at or above P (else 1), `σ² ← σ² / (1 + σ² I w)`, `θ ← θ + σ² w (o − P)`; prior θ 0, σ 1.5; σ² grows 0.02 a day away.
  - Observations (append-only): `{ source: 'director'|'grader', how, keys, level, outcome, assistance, misconception, repairs, responseId, evidenceId, supersedes, sessionId }`. The director's classified answers (correct 1, partial 0.5, misconception and stuck 0; a scaffold or repair card counts as half help); posed graded questions from `assess_answer`'s findings at the question's level. The rubric's grade replaces the director's reading of the same response; a corrected transcript replaces the original; evidence from before a topic's objective meaning changed no longer counts. Exams graded before the model are backfilled once.
  - Topics combine their own evidence with their observed concepts (ω² 1 logit² apart). Untested concepts and topics borrow from their topic, links and graph neighbours, wider (`estimates`; source `interpolated`, else `prior`).
  - Read by: `mastery_projections` and history after each observation (observed topics only; `displayIndex` = 100·P(apply), bands < 40 emerging, < 70 developing, else secure; capabilities P(recall), P(explain), P(apply), P(transfer)), so bars, the course tree, focus checks and goal modes read it unchanged; choosing goals by need (`estimates`: θ per topic; only a topic's own evidence in the secure band counts as understood); the director's card input (`conceptStates`).
- **Learner model v2** (`learner/v2.mjs`, system-spec §10–11; the same table, rows `{ v: 2, kind: 'observe' | 'expose', kcs, topics, kinds, … }`; no migration): keyed by the course model's KC ids (`<topicId>:k1`, the topic is the prefix). A KC's evidence also counts toward its topic's bar (ω² 1 apart), so projections, progress, the course tree and goals by need read it unchanged. `observe` with `kcs` goes to v2; with `keys`, v1.
  - `observe(scope, { kcs, family: E1–E10, regime?, rank: 1–5, outcome 0–1 (null only at rank 5), assistance? (else helpLevel/4), helpLevel?, wrongModelHits [{ id, p }], latencyMs?, hedges? (count or string[]), confidence?, steps? [{ kc (a subgoal key), outcome }], source, responseId, sessionId, cardId, itemId, difficulty? | level?, options? (closed item: g = 1/options), enacted? (cards.mjs LEVELS), taughtBy? { move (cards.mjs MOVES), act, representation, cardId, wrongModel }, repairs?, portionId?, affect?, trust?, reasoningShown?, explains? })`: known fields validated (`invalid_input`), others ignored, a step's `ok` read as its outcome; a retry (the same response with the same content) returns the stored row, while a resolution of the same response (another verdict) is new evidence.
  - **No evidence is dropped** (spec §10, §13 rule 6). `trust` (default 1) weights the observation both ways and the wrong-model update (likelihood ratio ^ trust): executed or exact verdicts 1, a judge its calibrated agreement, `uncertain` ≈ 0.3 with the verifier's leaning outcome (0.5 when it has none). Discrete credit needs trust ≥ .5: a hit counting toward confirmation, resolution, half-life, mastery. A correct attempt with `reasoningShown: false` counts 0.6 on success, raised toward 1 by the explanation that follows it (its own E5 observation: the one naming the attempt in `explains`, else the next E5 on the same item in the same session) by that explanation's trust × (2·outcome − 1); it gives mastery credit only once that reaches .5. A stated wrong belief is rank 5 with `wrongModelHits` and no outcome: the belief moves, θ doesn't. d = difficulty, else D[level], else the item's course-model level, else by family (E1 −1, E2 −0.4, E3–E4 0.3, E5 0.6, E6 0.8, E7–E9 1).
  - ponytail: an item's difficulty is its course-model level (D) or family, never learned from outcomes. Cross-learner calibration (level and item offsets, shrunk, re-centred so other learners average 0) waits until an anchoring offset shows once correct answers are recorded; in the real app each course has one learner, where only per-learner online calibration applies and the overall offset can't be identified.
  - Update (model.mjs `update`): `P = g + (1 − g)·σ(κ(θ − d))`, κ = 1/√(1 + πσ²/8) (the prediction averaged over θ's uncertainty; v1 rows keep κ = 1). Credit for a success × RANK_W (1, 1, 0.5 familiar, 1 with help in its assistance, 0 self-report) × (1 − assistance) × ENACTED (viewing 0, responding 0.4, changing 0.7, constructing and presenting 1); a failure counts in full, times 1 − 0.8·(wrong-model hit p) (explained by the wrong model), and nothing while viewing; rank 5 and E10 move no θ. A teaching move (`taughtBy`) adds σ² 0.2; σ² grows 0.02 a day; never past the prior 2.25.
  - Hierarchical prior (learner, topic, KC; σ² 1.25, 0.5, 0.5): pass 1 folds each KC from the flat prior and backs out its evidence; a KC's prior is its topic's mean given the learner's level from the other topics and the topic's other KCs (its own evidence left out); pass 2 folds each KC from it. A KC with no evidence of its own is `inferred` from the same prior.
  - `expose(scope, { kcs, portionId, readingEvent?, sessionId?, cardId? })`: reading is exposure (research/reading.md §7.6): presented, σ² + 0.2 + 0.05 per question, gloss or look-back, θ unchanged; a `read` what-works episode.
  - Wrong models: p from the model's prior. Whether a model fires on an item: yes (the item's `wrongAnswers` name it, or it is the model's separating probe), no (an executable detector's computed `wrongAnswers` leave it out), else unknown. A hit of strength h multiplies the odds by 1 + 7h; a success (≥ .8) on an item where it fires by 0.25, where unknown by 0.7 (each to the power 1 − assistance), where it doesn't fire by 1; a different wrong answer where it fires by 0.5. A repair move naming it (once per teaching card) multiplies p by 0.5 (REPAIR: the chance it took at once). suspected (a hit) → confirmed (hits on two distinct itemIds, p ≥ .7) → addressed (a repair) → resolved (an unaided success on a later calendar day); a hit sends it back; a suspected model below p .05 is dropped.
  - **Effective probability** (θ is strength with the correct model; a failure a wrong model explains is mostly explained away): `P(no wrong model fires) = Π(1 − p·fires)`, fires 0.8 (FIRES) where it fires, 0 where it doesn't, 1 where unknown (the conservative 1 − p). The prediction (`pEffective`) counts every wrong model of the KC at its posterior (its prior when untested); what is shown and ranked counts the open ones (suspected, confirmed, addressed): the map's strength and status, `priorities`' gap, and the topic bars and goals by need (model.mjs `shown` reads the topic estimate's `factor`, the mean over its observed KCs, and `cap` 69, below secure, while a KC has a confirmed, unresolved model). A confirmed, unresolved wrong model also blocks mastery and the map's secure.
  - `state(scope, kcId)` → `{ kcId, theta, sigma, source: observed|inferred, n, operative [{ wrongModelId, p, status }], fluency { medianMs, n }, flexibility { families, items }, halfLife (days; a first unaided success 1, a success after half a half-life doubles it, a failure halves it), due (1 − 2^(−age/halfLife)), dueAt, presented { how, portionId, at }, mastery { met, threshold, missing }, pEffective(d?, itemId?) }` (mastery: an unaided generative success E4–E9 and a rank-1 success; threshold or spine KCs two rank-1 transfers on different days; no confirmed wrong model unresolved). `pEffective(d, itemId)`: P(correct) on that item at difficulty d (logits or a level name; default the item's level, else apply) = P(no wrong model fires on it) × σ(κ(θ − d)).
  - `traits(scope)` → `{ learningRate { lambda, n }, readingSkill { wpm, comprehension, skims, n, level, factor (comprehension/.7 within 0.6–1.2; 1 when unknown) }, calibration { bias, resolution (AUC), n }, whatWorks(move?, kcKind?, representation?), representationResponse(elementKind, kcKind?), affect { recent, pattern }, helpSeeking { hintRate, meanAssistance, n }, preferences }`. What works: per teaching episode (taughtBy, deduped by its cardId) and KC, the residual of the first unaided outcome after it against θ before the move; a later day's replaces the same day's (weight 1 against 0.3); `{ mean (logits, shrunk to 0: Σw·r / (4 + Σw·P(1 − P))), sd, n }`. λ: the same residuals against a 0.3-logit gain, shrunk toward 1 (10 pseudo-episodes), within 0.3–3. Calibration: confidence counts 1, hedges 0.5 (0.45 hedged, else 0.8; −0.1 when over twice the median latency); a rank-5 claim or self-rating is scored by the next unaided outcome on its KCs.
  - `priorities(scope, candidates?)` (KC ids or `{ kc, leverage?, prerequisites? }`, default every KC) → sorted, each `{ …, priority, reason: gap|sigma|due|wrongModel, parts { leverage, gap, ready, sigma, due, wrongModel, recent } }`: spec §11 with β .3, γ .5, μ .8, δ .6; gap = max(0, .8 − effective P(apply)); ready = the weakest prerequisite's P(apply)/.7 (KC or topic ids); leverage 1 + threshold + spine + 0.1·dependents unless given; openWrongModel confirmed 1, suspected p, addressed .5 from a later day; recent e^(−hours).
  - `map(scope)` (`GET /v1/exams/{examId}/map`) → `{ canDo [{ kcId, topicId, statement 'I can …', strength (effective P(apply); null without evidence of its own), status: secure (≥ .7, σ < .9, no confirmed model unresolved)|growing|not_yet, mastered }], wrongModels (confirmed, addressed, resolved) [{ id, kcId, topicId, belief, status }], calibration { bias, resolution, n, line }, due [{ kcId, topicId, statement, dueAt }] }`. No θ numbers.
  - `coldStart(scope)` → `{ itemId (a course-model problem), kc, why }` | null: unasked problems on spine and threshold KCs while any has σ ≥ .8, then the rest, by the variance the answer would remove × leverage; null after 10 answered items or once every KC is that sure.

## Questions (`backend/questions`, `app.services.questions`)

- `available(scope, { knowledgeManifestId, topicIds })` → `[{ questionId, topicId, intendedDifficulty, objectiveVersionIds, exposed, dependencyCompatible, format?… }]` (no answers); `reserve(…)` → `{ question, reservation }` or `content_not_ready`; `release`, `extendLease`, `markDelivered` (→ `asked`, exposure, `question.asked`), `recordExposure`, `requestCustom` → `{ generationRequestId }`, `customStatus`, `get` (internal), `speakingForm` (no answer), `rubric`, `checkRendering(scope, questionId, text)` → `{ compatible, renderingId|null, reason }`; admin `supply`, `exposures`.
- Consumes `knowledge.published`, `personal.published`, `question.reserved`, `question.asked`, `question.invalidated`, `exam.deleted`. Jobs: `refill_question`, `generate_custom_question`, `author_exam_question`.
- **Typed inputs:** `inputKind` `speech|choice|multi_select|text|number|draw|order|match|exam` with `inputSpec` (choice and multi_select `{ options:[{id,text}] }`, order `{ items }`, match `{ left, right }`, number `{ unit|null, tolerance|null }`); the rubric carries `expectedStructured` for the exact kinds; an inconsistent spec never becomes ready. `speakingForm` and `question.ready.question` carry the input, never the answer; order items are shuffled, never in answer order. Choice, multi_select, order, match and number answers (`structuredAnswer`) are graded deterministically (number within its relative tolerance).
- **Exam problems** (`format: 'exam'`, filed under a unit): a course's own problem (from a pset or past exam) may have 1–8 parts and take 2–60 minutes; a generated one is planned at 2–6 parts; `title`, `setup`, `parts: [{ id, prompt, points, answer: { kind: code|latex|text|number|choice|draw, language?, starter?, choices? }, criterionIds }]`, `totalPoints`, `estimatedMinutes`; `voiceForm` is a one-line spoken introduction, never the problem. Authored by `questions/exam.mjs` (job `author_exam_question`, `exam` lane): plan, write (`EXAM_DRAFT`; part checks run: RISC-V on `shared/elements/trace.mjs`, C through `runC`), an independent solve, a compare that also counts each part's steps; one repair round, else `quality_gate`. The prelim bar (`exam_author_v3`): two or more concepts, at least one course trap, no one-step or warm-up part, a trace/derivation/code part, 12–20 minutes. Past-exam problems from the course (`looksLikeExam` files) are exemplars, never copied; a course problem (`fromCourse`) keeps its own setup and parts. Supply: `question_supply` rows `slot: 'exam'` (target `config.examQuestionsPerUnit`, default 2; the harness 0), one in the making per exam, focus units first. `reserve` hands out exam problems only on `format: 'exam'` or as the `preferredQuestionId`. Exam answers: `structuredAnswer { kind: 'exam', value: { [partId]: text } }`, graded part by part (number and choice exactly, blank `insufficient`, the rest by `localAssessor` on that part's criteria), recording `parts: [{ partId, points, earned }]`. The hopper's challenging slot asks for `transfer`.

## Understanding (`backend/understanding`, `app.services.understanding`)

- **Card v2** (`shared/cards.mjs`, shared with the page; `checkCard(card)` → `{ card, problems }`; `pageCard` drops `withheld`): `{ id, sessionId, n, issuedAt, goalId, goalTitle, source, move (probe|elicit|read|present|repair|scaffold|feedback|practice|metacognitive|affect), act, target { kc, topicId, statement, kind, spine }, helpLevel 0–4, intention, verdict { value, utterance, wrongModel, errorKind, trust, point?, late? } | null, say (≤ 4 sentences, ≤ ~90 words), ask, wait (recall|reasoning|work|reading), show (an ElementSpec checked by the registry's `checkElementSpec`, a reading `{ kind: 'reading', portion (inline), highlight }`, or a board), expect [{ id, kind (correct|valid_nonstandard|partial|wrong_model|stuck|done|question|term|skip|other), when, literal, wrongModel, pageState, reply, then { cardId, ask } }], neutral, handBack, persona, withheld { answer, solution }, why, item { id, family, regime, format } }`. `checkCard` flags a correct literal or the withheld answer in any voice field below H3, a reading whose purpose isn't said verbatim, reflex checks, long say, and **(§13 rule 7, verdict strength follows trust)** a `say` that opens a sentence with plain verdict words ("Yes", "Right", "Correct", "Exactly", "Not quite", "No", "Not yet", "That's wrong", …; `plainVerdict`) while `verdict.trust` < 0.95 (`PLAIN_TRUST`), or a neutral line with any; the engine strips them (`withoutPlainVerdict`) before a card goes out, its own and the writer's. `verdict.trust`: exact, executed and page verdicts 1; a verifier's its own (a judge ≤ 0.9, a concise exact mismatch 0.85); a detector's match its p (0.75; the marker alone 0.5); a verdict with no source of trust (a branch the reading picked on a card with no item) 0, never missing, since the voice reads a missing trust as exact. `verdict.p`: how sure the match to `wrongModel` is; the belief is said to be theirs ("Your idea is that …", "it isn't true that …") only when the verdict is plain and p ≥ 0.75, else "If you were thinking that …". The engine says a verdict plainly from 0.95, hedged from 0.6 ("I think that's right.", "I get something different for s4." with `verdict.point`, the first wrong part's label from the verifier, never its value; a catalogued belief is refuted as "If you mean that …: that isn't so." (it is known false; the hedge is on whether they hold it), a candidate claim as "I don't think it's true that …." (it is false only as surely as it was judged; below 0.6 "Let's test the idea that …."), a counter-case as "If your idea is that …, try it on this one"; "Talk me through why you think it holds" in place of "Why does that work?"), and below 0.6 not at all ("A common idea is that …, but it isn't so."). The writer's instructions say the same (`director_card_v9`, its input carries `after.trust`). The voice's text is stage's `actorCard` (never `withheld` or `why`).
- **Reads:** `understanding.courseModel/forKc/verify/separatingProbe/reading` (interface A; older slices normalized: facet → E-family, v11 kinds → F5/F7/F8); `learner.state/traits/priorities/coldStart/observe/expose` (interface B); `shared/elements/registry.mjs`.
- **Target and arc** (§11–12): the goal's KC (its own, else the top of `learner.priorities` among its topics' KCs). An arc is the session kind's slots (`policy.SLOTS`: learn `open, teach, engage, test, summary`; new_material; study_by_reading; repair `separate, repair, retest, summary`; consolidate; exam_practice; problem_help), filled by the dynamics model and replanned every turn; it ends with the target tested unaided, then the learner's summary, which closes the goal (`[Goal met]`); 14 cards without that moves on (still a gap, chosen again by need). An arc left open resumes in the next session on that KC. Card 1 says the target and its reason.
- **A turn** (`director.turn`, from `plan_turn`): the hold rule (a line that isn't an answer yet changes nothing; not on a draw card, where "done" is their answer); on a reading, "done"/"skip", a value said or a claim or request starts its after-move (when the line is their own answer it is the consolidation, never asked again) (exposure via `learner.expose`), a prequestion's answer is kept, a question or chat is the voice's. Then **step 1, the utterance type, before any correctness check** (`UTTERANCES`: answer, partial, request, claim, question, stuck, hold, chat): exact cues first (a literal match against the course model's verified answers and wrong-model answers, every number of the literal, number words only in short answers, short phrases not negated; requests such as read, show me, go faster, skip; claims such as "I get it", "I already know this"; "I don't know"; greetings; a question with no value), else the light classifier (`director_classify_v13`); a line stating a value is an attempt by its words. **Only an answer or partial work goes to `understanding.verify`** (6 s cap; late or failed is `uncertain`); nothing else is ever `incorrect`. A classifier's topic request is honoured only when it names another topic of the course (a request for the material is a reading; anything else is chat); a session kind only when it changes the kind. An incorrect answer with no wrong-model hit is a slip when P(success) ≥ 0.75 on observed evidence, a missing piece when a prerequisite is observed weak; partial work that doesn't check out is a pump, no failure. The verdict becomes a v2 observation (`kcs`, family, regime, rank 2 unaided-new / 3 familiar / 4 helped, outcome, assistance = H/4, wrongModelHits, latency, hedges, `taughtBy { move, act, representation, cardId, wrongModel }`, `options: 2` for yes/no; a rejected observation is logged); uncertain, requests, questions and partial work are not evidence; rule 6 holds the update until the explanation comes. `card.verdict = { value | null, utterance, wrongModel, errorKind, trust }`; `state().last.utterance`.
- **The §13 binding rules (8 Oct, after the first decisive test).** (1) At most one draw-out per answer: the voice's neutral line is it; the next card teaches (repair by kind, a ladder step, a worked step or a reading). (2) Never block a move on verification: a literal or detector match uses the card prepared before the learner answered (each card carries `detect: [{ wrongModel, cardId }]`, the repairs for the KC's likeliest wrong beliefs, besides each branch's `then.cardId`); otherwise the move goes out within the quick path (`QUICK_MS` 3.5 s; the classifier capped at 4 s, `PLATO_CLASSIFY_MS` overrides it for smokes of the late-reading path) as `pending`, and the verifier's verdict is attached when it lands (recorded, on `state().last.late`, and on the answering card by `card.updated` when they were right). **A late result can revise the move:** the classifier's reading (when it missed the 4 s) runs the same matching when it lands, and the late verdict brings its own wrong-model hits (p ≥ 0.5) or a wrong claim the calibrated `answer.unsupported` criterion found; a match is recorded at once and its repair card is issued for the same line (`respondsTo`), provided the learner has said nothing since and the board still answers that line (`state().last.revised`). One recorded hit per line: whichever lands first. (3) Every content-bearing line (answer, partial work, explanation, belief) goes to wrong-model matching, for every detector type, whatever its type: the marker prefilter (a cue phrase said in order, each word in any form, at most one other word between: "adds n bytes" for "add bytes"; its wrong model is listed first; it decides nothing itself and stands in only when the reading is unavailable; on the measured statements it finds the right model for 8.9% of belief statements, another for 0.9%, and fires on 0.4% of correct statements, where the snapshot's bag of content words had 25.8%, 12.9% and 11.9%), then the light classifier as the rubric detector (`director_classify_v13`: the known beliefs of the card's KC, its topic and any in the course sharing two content words with the line, most relevant first, ties to the first; the problem on the page and the correct idea in play; `agrees` is decided first and a line that agrees matches nothing; `wrongModelId` counts only with `beliefSure`; a decisive verifier within the quick path wins: "correct" overrules the label, "incorrect" with its own hits uses them). **Matching runs unless the verifier said correct or named the wrong model:** a verified `incorrect` with no hits is named by the reading's best match even when it wasn't sure (the verifier settled that it is wrong: p 0.6, 0.75 when sure), or by the marker only when there is no reading (p 0.5), then by a claim of their own (a candidate); a short value's reading is started at once and waited for only then; a late verdict names it the same way. A line whose value is already judged (an element's check of a spoken prediction, a literal) still goes to the matching when it says more (6+ words): a wrong one within the quick path, a right one late ("1012, but I still think it adds one byte" revises the move to the repair). The arc's last move no longer waits for a reading still on its way (10 Oct, below). A claim of their own that contradicts the idea and that no catalogued belief names (`contradicts`, `claim`, half its words theirs) is a **candidate wrong model** (spec §7 stage 12) with a stable id `cand:<kcId>:<hash of the claim>`, repaired as a false belief (F5) by its words. A match is the repair for its error kind, and the line is recorded as rank 5 with the hit (suspected; θ untouched). **The wrong model's id is on `card.verdict.wrongModel` (catalogued or `cand:`) and in the observation's `wrongModelHits`.** A verified wrong claim (`answer.unsupported`) is refuted only in the words the reading gave it, never made up from the line itself; with no such claim it is a hedged "I get something different" and the ladder. The same line again on the same KC in a session (hedges and punctuation aside; four words or more) is matched the same way with no model call (`how: detector:remembered`), and the classifier's reading is one call per session, card and line, so identical input gets the identical type and match (the replyLight lane takes no temperature or seed; this is its lowest-variance setting). (4) A false belief gets the direct refutation: "Not quite: it isn't true that …", why it seemed right, what's true (the KC's core statement), then a new case whose answer the refutation doesn't say aloud (else the question again); the same wrong model or claim again, however worded: refutation, then the right way worked, then a counter-case; **an arc never closes over an open wrong model** (`policy.openModel`: a suspected or confirmed model on the KC with p ≥ 0.3 not repaired in this arc, or a claim refuted and not yet answered right): its test and summary slots and its end become the repair, and when the session ends first, `goals.needs` puts that KC first next time; a covered KC is not re-announced in the same session (`closedKcs`); a flawed model (F7) is run to a contradiction first ("Your idea is that …; try it on this one"). (5) Never affirm an unverified claim, and a draw-out on an answer not verified correct presupposes nothing: "Why does that work?" only after `correct`. (6) Elements carry a task: a KC with a runnable element is engaged through it with predict (only where a checkpoint can be held), change or construct; a compare or change element also carries an item whose answer is evidence.
- **§13 rule 8, close the contrast, and when to repair (decisive2 stage 1).** A model is repaired only when it is sure (`policy.sureOf`): confirmed for this learner; a new match on a model with standing before this line (confirmed, addressed and back, or suspected at p ≥ 0.5: the second piece of evidence; decisive6 had a confirmed model, repaired then restated, sent to step hints because the restatement came through the marker alone at p 0.5 while the model read `addressed`); or a hit at p ≥ 0.75 with no rival within 0.2. A hint is for an error of another kind. Otherwise the move is the separating probe (`separating_question` via `understanding.separatingProbe`, at most twice an arc, the card naming no model: `verdict.wrongModel` null, `state().last.hypotheses`), then a hint; the arc-close guard and the arc's repair slot probe a suspected model the same way instead of repairing it. A bare value ("7", six words or fewer, with a value) is named by the reading only as a hypothesis (p 0.5: the separating probe tests it, nothing repairs it); the verifier's hits and the engine's **computed match** name it outright (the line's values against each wrong model's predicted answer on the item, `predictedWrongAnswers`, less the values the prompt gives; p 0.75 for one model, 0.5 each when two give the same answer, so they are told apart first). Once a model is sure: if the learner just answered a checkable case (an item, or an element's prediction) by it, the repair is `contrast` (F5, F7 and F9 start there; any repair answered by it again does too): both results side by side, why they differ, then a fresh case (never the one just shown, never one whose answer the card says; else "In your own words: why do the two differ?"). The contrast is computed (`contrastFor`) and always on one case (decisive3 L2). **When they answered the case on the page** (`answersCase`: a short value line, or a line with at most one number the case doesn't give; a line quoting a case of its own answers nothing on the page, nor counts as an element prediction), the contrast is that case only: their own answer (their one foreign number, of the same kind as the key's value, within 100×) against its key or the element's truth, else that item's own predicted answer; never another case's numbers. **When they stated the belief, or answered a case of their own**, another item's predicted answer may be used, said and shown as a new case ("Take another case, on the page: by that idea, …; in fact …", board "Another case"). A contrast is never repeated: each item at most once an arc (`arc.contrasted`, never asked again either), and `issue` drops any sentence of five words or more already said in the session (`saidKeys`); a late revision that would add nothing new is not issued, so it never replaces a card. A general hint already said is replaced by the item's own step. For a value: their own answer against the item's key ("With your rule it's 1003; it's actually 1012, because pointer addition already scales the three-element offset by sizeof(int)."; hedged: "You said 1003; I get 1012, because …"); for a statement, the course model's prediction for the belief on one of its items, against that item's key, with the case on the page ("On the case on the page, that idea gives: …; in fact: …, because …"), else their answer against the item's answer. A refutation's first statement carries one computed contrast when the belief is computable ("By that idea, a + 3 gives address 1003; in fact it's 1012, because …"), and an F7 or F9 counter-case with nothing to run is shown computed, never left for them to resolve. The page shows the side by side (`Side by side` board: the case, their answer or the belief's, what actually holds, why they differ, then the new case).
- **Never silent, one case, no naming without it (decisive3/4).** Every content-bearing line gets a card that `respondsTo` it within the quick path: a long line the reading couldn't read is `unverified` on a card with an item (never judged; rule 12's generative check follows) and `answered` elsewhere (the next move); a turn whose card was replaced meanwhile by one answering an older line still issues its own; the writer, its failure and the watchdog never issue for a line a newer one followed; with nothing left to open, a generative check. A right answer gets a specific confirmation when the key is a short value (`verdict.confirm`: "Yes, 1012."). **A value a model computes is a candidate, not a diagnosis** (`byValue`: the computed match, a literal wrong-model branch, a page or spoken-prediction signature, the verifier's hits, a bare value's reading): the first such match gets the **unattributed contrast** on their own case ("You said -31; it's -1, because …", no belief named, safe at any p) and a fresh case that separates the candidates (the lead candidate computes an answer other than the key there, rivals another; `separatingFor`, else `separatingProbe`); the card carries the candidate as `verdict.wrongModel` with `suspected: true` and value `incorrect` (never said); a second matching answer in the arc (or the learner model's confirmation) makes it sure, and the attributed repair follows ("With your rule it's 0; it's actually -8, because …"). A belief they said is sure at p ≥ 0.75 as before. **A belief is named only beside a computed case:** every repair on a computable belief shows one (their own case, a new case said as new, or one shown earlier recalled: "As in the case on the page: …"), computed before the card is built; a refutation or counter-case with no case to show names nothing ("Here's what's true: …", then a case whose answer by the belief brings the contrast); course text keeps a contrast clause only on a card showing a case, for a sure model; hints, separating questions and explanations never name. Nothing is said twice: sentences of five words or more said in the session are dropped from later cards (`saidKeys`).
- **Refute only a belief verified false (decisive4).** A catalogued wrong model is verified by the course model. A candidate claim (`cand:`, no catalogued model names it) is a hypothesis until the calibrated narrow judge finds it false (`answer.unsupported` against the KC's statement and explanation, job `director_claim`; `state().claims[id]`: true judged false, false judged supported, null being judged); a claim V8 already judged wrong in their answer (`answer.unsupported` on the item) is proven at once. An unproven claim's hit carries `unverified: true`: never sure, so its move is a case to try their idea on (`counter_case`, `unverifiedClaim`, naming nothing; with no case left, a worked case or the explanation), never a refutation, a contrast, an "in fact" or a negative verdict; its rank-5 observation is held and recorded only when the judge finds it false. A claim judged supported is no belief: the line goes on as content. The memory re-matches only the same proposition (the same normalized line) for a catalogued model or a proven claim; any other line is read again. No sentence is said twice, but a repeat never strips a card's substance (a frame alone is never voiced); a case shown in the session (`shownCases`) is never contrasted or asked again, and a counter-case with no case left becomes a worked case.
- **§13 rule 9, deny nothing they haven't shown; revoice what they have (decisive6).** Every course-model card (built, safe, revised) passes `presupposeNothing`: every negated clause goes (", not Y", "Y does not …", "; Y doesn't", "isn't Y", "is not Y", "never …", "rather than Y", "instead of Y"), in the voice fields and on the page; a sentence left empty, or with only its frame ("Think about this:"), goes. Protected, kept as written: the question on the page (the item's prompt and answer), the case, key and answer a contrast shows (`card.contrast.{truth,mine,prompt}`), the learner's revoiced words (`card.revoice`), an opener the builder made for a sure model beside its case (`card.keepText`), and the verdict leads ("Not yet."). Hints are built from the first sentence with a positive form. A contrast's "because" is the key's true reason, positive and on that case (`reasonOf`: the key's own reason, else the explanation's first positive sentence whose numbers the case has; never another case's worked example). **An unproven claim** (a `cand:` not yet judged false, or any candidate not sure) **is revoiced** once in the arc, in their own words, as a question, with no "not" and no correction (`revoice`, move `elicit`: "So you're saying moving molecules across a membrane always takes the cell energy?"; their hedges and reason dropped, first person turned to second); it is that answer's one draw-out. Their "yes" (`AFFIRM`) confirms it (`revoice:confirmed`) and a case follows; anything else is read as usual. After the revoicing: their answer to a case, judged wrong by the verifier, gets the unattributed contrast (their answer, the key, the reason), else a case. A candidate is never told apart by a separating question (it has no computed answers), and a separating question names nothing.
- **Never silent, at the turn level; replies to a revoice; repair first (decisive7).** `turn()` wraps the whole turn: after it, a learner line with no card answering it (`respondsTo`) gets one. Exempt: a hold, noise ("um", "hmm"), a real question (wh- or auxiliary-led with "?": the voice answers it and hands the card back), a question or the prequestion while a reading is open, the writer still on it, and a newer line. The move: the open question again, more simply (`elicit/reask`: same case and branches, no verdict, "Just your best guess: what do you get for the question on the page?"); asked again, or with no question open, the next step (a hint via `stuck`, or the repair due). A bare acknowledgement ("ok", "alright", "fine", "cool", "thanks"; not "yeah" or "right") is never judged as an answer (`how: ack`). A reply to a revoicing: "yes" confirms it (`revoice:confirmed`); "no" or a correction drops the claim (`claims[id] = false`; a bare no moves on, a correction is read as new content); a hedge ("kind of", "not sure", "maybe"), an acknowledgement or a few words take it as tentative (`tentative_claim`): the case comes at once (`counter_case`, naming nothing) and their answer on it decides. **Repair first:** a model confirmed for this learner and not yet repaired in this arc gets its repair before any generic move (a pending answer with no match, stuck, incorrect, a slip, a missing piece, an answer to a non-question, the next slot), unless their latest error matched another model or they asked for something; inside an arc's repair sequence (contrast, fresh case, worked example) the usual moves follow.
- **Repairs recorded when delivered; a worked example's answer is evidence (decisive7, §10).** A repair card issued for a sure model (its `verdict.wrongModel` is the arc's repair target, move `repair` or the sequence's `worked_example`) records at once a rank-5 observation with `repairs: <model>` and no outcome (θ untouched): the model reads `addressed` whatever they say next, and the next answer's observation (same card in `taughtBy`) counts the repair once. A worked example is followed on the same card by the matching item done alone (same family, else KC; a question board; a different answer): its answer is verified and observed like any other. With no matching item, their self-explanation is an E5 observation (`card.explains`), judged like any explanation. A board's paragraphs are kept (`clipPage`), and rule 9's filter reads a page line by line.
- **A belief said in a sentence gets a real contrast (decisive9).** For a catalogued model with computed cases: a new computed case ("Take another case, on the page: that rule gives 0; in fact it's -8, because …"). Otherwise (a `cand:` judged false, or a model without computed cases): their words, then the course's full reason (`from: 'said'`: "You said: X. As I see it: Y."), Y being the key of the case on the page when it is a statement not yet shown (decisive8's targeted contrast), else the explanation's positive sentences (up to two, no case's numbers, none said before). The new case follows: an unused item of the KC, else the KC's board (a representation to change and watch), else their own words ("why do the two differ?"); never a question already asked in the arc. A short line with a value is an answer to the case; a sentence is a belief, whatever number it mentions. The same claim in another word order is the same candidate (its id hashes the sorted words). No sentence of five words or more goes out twice in a session: the builders choose new substance, and `issue` drops any repeat; a re-asked question is said as one ("The same question once more."), never "new case".
- **A stated belief's contrast shows a case it gets wrong, from verified course content (decisive10).** In order: a catalogued model's computed case (the case on the page, said as this case; else another, said as new; never one already shown, under any id); else a course case paired with the belief by the calibrated narrow judge (`director_pair`, after a claim is judged false or when a catalogued model without computed cases is stated: `answer.unsupported` with the belief as the answer to each case, against the case's own text; `pairs[id]`). Only cases on the belief's own subject are paired (decisive11b): the KC's, then its topic's, that share a word of what the belief says beyond its KC (its words not in the KC's statement or explanation: for "moving molecules across a membrane always takes the cell energy" on a diffusion KC, "membrane" and "cell", never "molecule"), most shared first, at most four. `director_pair` also asks the light lane (`directorWriter.quote`, `director_quote_v1`) for the case's one sentence the belief can't account for, kept only when it is a verbatim substring of the case text and a statement of what happens (never a setup instruction or a tutor note), else no pairing. No calibrated criterion verifies that a sentence contradicts a belief (evals' set: answer.correct/mechanism/unsupported, entail.supports, drawing, history), so the case is asked about, never asserted against them: "You said: <their words: their line, the claim they confirmed, or a right answer's reason>. Here's a case from the course: "<that sentence>."", the case on the page by its content (never its title: a tutor-facing label, often written as the misconception it targets), its setup without notes to the tutor and through rule 9's filter, ask "How does your idea fit that?" (a refutation shows a case the same way; no other repair carries one). Else their words and the course's full reason, then a new case. A claim they confirmed on a revoice ("yes") is contrasted in its own words, never in the words of the "yes". Nothing is generated: the case and its outcome are the course's words; only the pairing is judged. **One revoice per belief per arc, across rewordings:** the session's own claims (`claimWords`) join the beliefs the reading matches against, so a rewording matches its candidate by meaning.
- **Right answer, wrong reason (decisive8).** A literal branch is the voice's ("If exactly") only when the line is that answer alone (`cards.alone`: nothing beside the literal but filler words); then its prepared card follows (`spoken: true`). With anything said beside it, the voice waits and the engine's card decides, with the verdict in its lead. A right value (a literal, an element's spoken check, or the verifier on a card with a literal key) that comes with a reason has the reason matched within the quick path, like any stated belief: the reading (the session's own claims joined), a remembered line, the marker standing in only as a hypothesis (p 0.5). A match keeps the verdict and rides on it (`reason: true`, its hits on `wrongModelHits`): sure → rule 8's contrast on the reason with the answer confirmed in one sentence ("0x1004 is right, but adding 3 here moves three ints, 12 bytes; with your idea you'd get 0x0FFB.", the case on the page when it is computable there, else another computed case, a paired course case, or their reason against the course's full reason); a claim not yet judged false → the confirmation, then their reason revoiced as a question; a guess → the confirmation and the separating probe. Never a bare "yes". The attempt is recorded with its outcome and `reasoningShown: false`; a reading that lands late revises the move the same way (the reason's match recorded as a rank-5 belief). An explanation the verifier judged right is its own reason: the judge's verdict stands.
- **A page prediction said aloud (decisive8, §10).** The page's E4 row for the card in play is held `HELD_MS` (8 s): the line that says it claims it (its response id on the row, one row per attempt); unclaimed, `director_held` records it as is. A line checked by voice first still makes the page's row skip (`spokenChecks`).
- **Their reply to a course case (decisive11b).** The case card's question ("How does your idea fit that?") makes their reply an explanation of that case (`explains` = the case id). In the quick path, alongside the reading, the calibrated criteria judge it against the case's own text (`judgeReply`: answer.mechanism, and answer.unsupported as a fault; the same judge the explanation job uses for items). Judged the course's account → confirmed specifically ("I think that's the course's account of that case.", as strong as its trust) and on. Else, or not back in time → rule 8 on it, nothing asserted: "You said: <their words>. The course's account of that case: "<its outcome, the case's first statements of fact>." <the course's reason>." with the case on the page, then a new case. The reply is recorded once, as an E5 with the judge's outcome and trust (the light reading if the judge is unavailable); a judgment that lands late and finds the course's account goes on the card that answered them (`card.updated`, verdict correct).
- **An arc closes confirmed (decisive12).** A summary is an explanation of the KC (`explains` = the KC): judged in the quick path against the KC's statement and mechanism (`judgeReply`), recorded once as an E5 (no item). When an arc closes on a right answer or a summary judged right that the voice hasn't confirmed, the closing card (the next arc's opener, or the check) opens with it, specifically and in the course's words, as strong as its trust: "That's it: <the KC's statement, its first clause>." at plain trust, "I think that's it: …" when hedged, nothing below; the card carries that verdict.
- **Elements and readings central (after decisive12: 78% of course-model pages were markdown, 0.3% readings).** (1) Readings: the zone is θ against the portion's level (the wrong models' folding no longer puts most KCs out of zone); only an exposition (a present, read or repair move) takes the arc's teach slot, so an opening prediction leaves it; a first attempt that misses before the telling gets the telling, not a hint ladder; and in learn, new-material and study-by-reading sessions a KC's first exposition is its reading portion when one is in zone (purpose, the prequestion, quiet reading, one consolidation after). Kept as markdown: worked solutions, rule 8's side by side, long questions. (3) Rule 8 on the page: a repair showing a computed contrast with no new case of its own asks stage's `elements.generate` (background job `director_compare`; kind from the KC's representations, mode change, the case with its key, the wrong model with its computed answer) for a compare element, their rule beside the true run; when it lands and the card is still in play, the card's page becomes it (`card.updated`). - **Readings framed in full, through rule 9 (decisive13).** A portion's purpose and prequestions pass rule 9 (`framed`): a clause that denies, or a word only an unsure belief uses (its words beyond the KC's statement and explanation), drops it. The purpose falls back to "Read to answer this: <its first fair prequestion>", else "Read it through for the idea at work here"; a prequestion falls back to one from the purpose ("What's your guess: why …?") or the portion's after-question. The card's say carries the purpose, "Before you read, think about this: <prequestion>", and the minutes and one question after, verbatim. "Done" is always followed by the one consolidation, ahead of any repair and past the arc's card limit. Rule 9's negation forms add "neither … nor" and "no X or Y". A generated element's kind comes from its topic's other KCs' representation kinds, else the content's shape (dates → timeline, never without; values → numberline; epistemic → argmap); none fits → no element.
- **Guide mode (12 Oct; docs/teaching-redesign.md, docs/teaching-guide-spec.md).** New material is taught from a **section guide** (`backend/lessons/guide.mjs`, built in code from the section's course-model slice, else its notes): the story, the ideas in order, boards the tutor may show, optional questions with verified answers, the usual confusions. The guide card (`act: 'guide'`, `guide`, `thread`) is the voice's resource, not a script: the voice chooses each move (tools `show`, `move_on`, `practice`; `POST /v1/sessions/{id}/guide`). The walk is one goal per section, the section alone (`sectionGoal`). Practice and exam problems (asked for, `practice`) keep the arc engine. `change_topic` moves only to a real section of the course or "from the beginning"; anything else is refused. Misconception probes (separating questions) need two answers on the idea (`novice`).
- **Resume, a short intro, lecture order, pacing (the user, 10 Oct).** `POST /v1/exams/{id}/sessions { resume: true, sessionId? }` returns the learner's open session for the exam (the given id, else the newest) when it was active within 3 h: start's fields plus `resumed: true`, the current card, `sequence` (the newest server event, to subscribe from) and `spoken` (Plato's last 60 voice lines, oldest first, `{ text, at, interrupted }`); else a new session, `resumed: false`. The intro is a greeting and at most two questions (their aim, the exam and its date; where they are in the lectures, kept as `exams.lectureFrom`); how they like to learn, their background and what they find hard go on a background goal, asked at a natural pause; there is no diagnostic block. The agenda walks the course in lecture and section order (the course tree's walk, each section's KCs in the course model's order) from where they said they are ("lecture 5" is the unit whose outline lectures begin with Lecture 5, else the first unit after it), else the first section not yet shown known; a section whose slice isn't built yet is taught from the notes in its place, never skipped (11 Oct). The walk's position persists: a walk goal that finishes sets `exams.walkAt` (a KC goal's own section, for its other KCs; after a notes section, the next one), and the next session resumes there; saying where they are in the lectures again clears it. A notes section closes on evidence like a KC arc: 2 right answers on it, else 8 content lines (`NOTES_RIGHT`, `NOTES_MAX`), then the next section opens; by need (spec §11) only for a pressed topic and in review or exam practice. Teach first: a section starts by teaching (learn: teach, engage, test, summary; new material: read, after, test, summary): a reading in learn sessions, else an explanation, a worked example or an element to change, then light engagement ("Try this one with me"). A test comes only when the learner model says they should know it (predicted success on a core item ≥ 0.7, `READY`), else practice first, at most twice; or when they ask to skip ahead. When they say they already know it, one quick check confirms it and closes the section. No dead air: on the writer path (no course model; a few seconds on the Fast tier) the writer's card goes out when it comes; if it isn't in within 5 s (`WATCHDOG_MS`), a reading from the notes (else the safe move) stands in (`lateFor`), and the writer's card still takes its place unless a newer line came (11 Oct: a stand-in on every line, then the writer's card, was two cards per answer). An intro question (their aim, where they are in the lectures) takes no model call: any line that isn't a greeting, question or request is the answer, and a lecture number said with their aim counts as where they are; the arc's last move no longer waits on a late reading. Arc limits are 14 cards, 24 with a misconception open. **Exam-aware pacing (11 Oct):** within `CRUNCH_DAYS` (7) of `exams.examDate`, a new KC's arc is `teach, test` (learn and new-material sessions: no engage slot, no summary, no reading portion as the exposition, one round of practice before the test at most) and its limit is 8 cards, 14 with a misconception open (`arc.crunch`).
- **"Without Y" (decisive11b).** Rule 9's filter (`cards.positive(text, protect, unsure)`) also cuts a "…without Y" phrase when Y names a belief not sure for this learner (two of its words in any form: the KC's wrong models and their beliefs' cues, their own claims this session; not a confirmed model, nor the one the card repairs as sure). "Without changing its transport properties" stays; "without costing the cell energy" stays in the reason when that model is sure. Every course text the learner sees or hears passes it, a course case's setup included; only the question on the page, a key, their own words and an opener for a sure model are kept as written.
- **No attempt unrecorded (decisive11b).** A repair with no question of its own that shows a case on an item ("why do the two differ?", "say what is really going on") asks them to explain it: `explains` = that item, so the answer is an E5 judged by the calibrated criteria. A repair that has no case left recalls the last one shown ("As in the case on the page"). A line the reading couldn't type in the quick path (`unverified`) keeps its verifier: once the late reading says it was an attempt, the verdict is recorded.
- **Presupposition in content (§13 rule 5).** Every course-model card (cardFor, the safe move) passes `presupposeNothing`: a contrastive clause in course text (", not Y", "rather than Y", "instead of Y", and the parenthetical ", not Y,") is kept only when the wrong model behind Y (sharing a content word with Y) is sure for this learner (confirmed, or suspected at p ≥ 0.75), or is the one the card repairs; else it is cut (a hypothesis presupposes nothing), in say, ask, hand-back, branch replies and the page. ("…depends on the width of the interpreted value, not its storage container" → "…depends on the width of the interpreted value".)
- **Evidence (spec §10, updated):** a prediction said aloud on an element card is an attempt checked at once by the element engine's `check` against its truth (E4, rank 2, trust 1), keyed by the response id; the page's later event for that card is not counted again. Every attempt is recorded at once with `trust` (exact or page 1; a verifier's; `uncertain` 0.3 with the chain's leaning as outcome); `reasoningShown: false` on a correct attempt with no reasoning (rule 6: the move waits for the explanation, the evidence doesn't); the explanation is its own E5 (`explains`: the attempt's responseId), judged in the background on the calibrated `answer.mechanism` and `answer.unsupported` (`understanding.judge`, trust = their calibrated agreement), else a light reading at 0.3.
- **The policy** (`policy.decide`, first match, §13): 3 a request (read → a reading, else the spoken explanation; talk → a worked example or explanation; hint or answer → one ladder step; skip; a session kind; a topic → `change_topic`'s path); 9 frustration after a failure → a bounded choice; 12 "I get it" → a generative check (self-report is rank 5 calibration data); 1 uncertain → never a guess and never a second draw-out (the voice's neutral line drew them out): a likely wrong model is told apart by the separating question, then repaired by its kind; else the telling the arc hasn't made yet (explain or try first, by the dynamics); else one hint; then on; 4 no attempt → ask for one, once; 6 correct with no reasoning or hedged → ask why (after a literal match only: after any other answer the voice's neutral line already asked for their reasoning, so the card says the verdict and leaves the turn with them, no new question, §13 rule 1; their reply is the explanation, matched like any content); 5 correct with reasoning → verify and extend (the arc's next move; a fast explained first answer skips the telling); 7 slip → indirect flag, then locate; 8 wrong model → `separatingProbe` while unsure which (p < 0.6 or two close), then repair by error kind (`policy.REPAIR`: F1 flag, F2 vary the surface, F3 strategy prompt, F4 detour, F5 refutation (a refutation reading when in zone, else spoken: the belief quoted, why it seemed right, the KC's truth), F6 contrast the step, F7 run their own model on the page (`task.prediction`), else a counter-case, F8 the new frame plus two cases, F9 counter-case, F10 back to the text, F11 the field's standard of evidence and the counterargument, F12 a generative check), then a re-test on a matching item; 9 missing piece → a detour to the weakest prerequisite; 10 stuck → one ladder step (H0 pump, H1 general hint, H2 specific hint, H3 tell one step, H4 the worked solution then a matching item alone; never two levels unless frustrated); 11 two failures at H2+ → an easier item or another representation (0.8 aim); 13 otherwise the arc's next move (items at ≈ 0.7 predicted success, `pEffective`). Below H3 the answer is in `withheld` only.
- **Reading moves** (§13, research/reading.md §7): long exposition goes on the page when in zone (prerequisites not observed weak, `pEffective` ≥ 0.6 at the reading's level: intro below θ 0.5, core, advanced above 1.5): `understanding.reading` → a `read` card (`wait: 'reading'`, the purpose verbatim, about N minutes, one question after, the first prequestion as `ask`; branches done/question/term/skip), then one consolidation from the portion's `after` (a prequestion's answer comes back first). Out of zone or none: the spoken explanation with the thing shown.
- **The learning-dynamics model** (`dynamics.mjs`, §5): `PRIORS[kcKind][act]` (domain-generality §6.4), × the adapter's emphasis (§7.7, `ADAPTERS[a].moveEmphasis`: ↑↑ 1.5, ↑ 1.2, ↓ 0.7), × the state interaction (expertise reversal for worked examples and telling, a moderate-gap bell for try-first, strength needed for retrieval, interleaving, construction and teaching), × the learner's posterior `exp(0.5·whatWorks.mean)` (also per representation); `choose` ranks by gain per minute. Evals' worlds scale `PRIORS`.
- **Elements** (§15b): a move's mode (predict, change, compare, construct, teach, draw) picks among the KC's representations whose registry kind supports it (`chooseElement`: `bestFor` against the moment, the learner's `representationResponse`), else the item's own `element`; checkpoints come from the representation, else the engine (`endCheckpoint`: the last step's changes, the engine's values as the truth and the correct literal); repair runs their own model (`task.prediction`), teach shows the classmate's attempt (`task.attempt`) with `persona`, draw is a canvas (the representation as the reference, its `notice` as the rubric), compare pairs two instances. Items with no element show the question as a board ("The question").
- **Speculation** (§16): before a card goes out, each branch the voice can match (correct, every wrong model, stuck; a reading's done and skip) gets its follow-up decided by the policy and built (no model call), so a literal answer's next card is out in under a second.
- **Fallback, no course model:** card 1 quotes the notes on the goal's topic; each answer goes to the writer (`director_card` kind `answer`, `director_card_v9`, card v2 drafts, streamed: its core goes out once say, ask, neutral and a branch are in; its expected answer checked by `verifyBranch`, a wrong one withheld) behind `director_watchdog` (20 s).
- **Resilience:** a failed or late model call, or a turn that throws, ends in the safe move, never silence and never the neutral line a second time (§13 rule 1: it was said while the move was made): with a course model, one general hint from the KC (H1); without, a reading from the notes on what they said (`act: 'read'`, a notes board; no model call); else a question that keeps them working. On the writer path (no course model), a second line while the writer is still on the last one gets that reading at once, and the writer's late card is dropped as stale. Neutral lines rotate so none repeats within four cards.
- **Evidence** (`POST /v1/sessions/{id}/evidence { events }` → 202 `{ accepted, observed, exposed, ignored }`; `evidence.mjs`): element events (interactive §9.3) become observations weighted by the enacted level (`revealed` E4, a `signature` folded in as a wrong-model hit; `constructed` E8 with the first failure; `taught` E5 when scored; `drawn` E8 when scored, else (the drawing reader's `reading` and the task's `rubric`) scored per rubric element in the background by the calibrated narrow judge (`understanding.judge('drawing.shows', …)`, job `director_drawing`): met only on a yes, discussion-only (no credit) when not calibrated; a reveal of their earlier answer or the classmate's is not new evidence; hints count as help); a reading event becomes `learner.expose`. A page result on a construction they said they were done with is their answer (`director_page`). Unknown types are ignored.
- **think** (`POST …/think` → `director_think`, `director_think_v7`): the notes' passages plus the course model's explanation of the KC in play, never the answer of an open question; `topic-change` as before. **state** → `{ cardId, n, arc, last { verdict, trust, how, rule, move, act, helpLevel, wrongModel, errorKind, next, … }, intro, page }`; `current(s, { full })` (full includes `withheld`).
- **Lanes:** `replyLight` for classification and checks, `director` for writer cards and think; no model call for card 1, literal matches, prepared or built cards.

## Courses, elements and the runner

- **Courses** (`backend/exams.mjs`, `app.services.exams`): `create`, `patch`, `remove`, `get`. Hooks `examCreated`, `examPatched`, `examDeleting` and `examDeleted` let modules react. Deleting a course is the `delete_exam` job: its data goes, a `tombstones` row stays, and `exam.deleted` is emitted.
- **Elements** (`backend/elements`, `app.services.elements`): `create`, `notes`, `build`, `generate`, `problems`. These sit behind `POST …/elements` (a visual made in the background while Plato talks) and `POST …/notes` (search the learner's notes; changes nothing).
- **Runner** (`backend/run`): `runC` compiles and runs the learner's C under `sandbox-exec` (macOS only). It allows no network, no file writes and no other programs, with 2 s to run, 10 s to compile and 64 KB of output. `runJs` runs the course model's checks the same way. Behind `POST …/run`.

## Local server (`server/`)

`server/index.mjs` serves the backend, the page (Vite in development, `dist/` with `--production`) and three routes of its own. It accepts only `127.0.0.1` and `localhost` hosts.
- `POST /api/session`: a short-lived ElevenLabs credential for the actor agent. That is a WebRTC token, or a signed WebSocket URL for a text-only conversation. The API key never reaches the browser.
- `GET /healthz`: `ok`.
- `POST /actor`: Plato's turn on the student's provider (signed in). `POST /check`: a second model's check of his verdict. `POST /voice/tts`, `POST /voice/stt`: ElevenLabs voice on the student's key (`/settings/voice`).

`server/runtime.mjs` runs Codex (`codex app-server`, ChatGPT sign-in) in lanes. The reply path has its own lanes (`director`, `reply`, `replyLight`, `elements`), so it never waits behind background work (`heavy`, `exam`, `light`). The reply-path lanes run on the Fast service tier (`priority`; `PLATO_REPLY_TIER` overrides it). The voice is `gpt-6.1-sol` at low effort, its lowest; ElevenLabs refuses `none` for it. `PLATO_FAULTS` injects per-lane failures and delays in development.
